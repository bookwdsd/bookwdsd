## 🛠 项目经历

### 1. Snap — 支付后的意义确认器（独立开发 · 进行中）

- **定位**：在支付完成的那一刻，用一次轻量确认记录这笔钱「为了什么」，把消费从"事后对账"变成"当场确认意义"。
- **核心流程**：AccessibilityService 监听支付完成页 → 悬浮窗弹出（不打断主流程）→ 选择分类 / 补充备注 → 写入本地交易库 → 摘要页与列表页回顾。
- **技术栈**：Kotlin + Jetpack Compose + Room；规划中：NotificationListenerService 解析银行 / 微信服务号通知，补全资金来源。
- **六阶段路线**：

| 阶段 | 内容 | 状态 |
| --- | --- | --- |
| 0 | 零骨架（工程结构 / 依赖 / 主题） | ✅ 完成 |
| 1 | 采集层（无障碍事件 → 支付页识别） | ✅ 完成 |
| 2 | 数据层 + 手动分类（Room 表结构 / 分类器） | ✅ 完成 |
| 3 | 悬浮窗弹窗（WindowManager + Compose） | ✅ 完成 |
| 4 | 智能预选 + 待处理队列（摘要页 → 交易列表 → 待处理队列 → 账户识别 → 推送 → 资金来源） | 🚧 进行中 |
| 5 | 打磨（动效、稳定性、上架准备） | ⏳ 未开始 |

- **已知技术难点**：微信支付成功页与输入页不显示付款方式，仅预支付确认 BottomSheet 可见；资金来源需从银行服务号通知反推；MagicOS（实机 荣耀 BRC-AN00）对后台存活与无障碍权限有额外限制。
- 详见 [`docs/snap.md`](./docs/snap.md)。
