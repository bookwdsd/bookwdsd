# 项目详解：Enbuild 与 Courtside

## 一、Enbuild 应用框架引擎——企业应用软件一站式解决方案

> 团队竞赛项目 · 2025 · 第九届吉林省中华职业教育创新创业大赛三等奖

### 1. 背景与定位

面向中小企业的后台系统快速生成工具。目标不是"功能大而全"，而是让企业以低成本搭起一套可维护的管理系统。

### 2. 我的角色

项目负责人 / 核心开发：

- 需求调研：带队走访 10 余家本地中小企业；
- 技术选型：React / Vue 路线之争的决策；
- 功能取舍：砍掉华而不实的功能；
- 核心模块实现与团队分工协调。

### 3. 关键过程

| 节点 | 发生了什么 | 我的应对 |
| --- | --- | --- |
| 第一次内部演示 | 系统崩溃，连基本表单都无法提交 | 提议暂停争论，回到"用户到底需要什么" |
| 需求调研 | 走访 10 余家企业，发现客户最在意部署与维护成本 | 果断砍掉冗余功能，聚焦核心流程 |
| 技术攻关 | 一个关键 bug 试了 7 种方案 | 第 7 次在凌晨跑通，靠的是逐项排除而非运气 |
| 团队低谷 | 队友因进度压力情绪低落 | 不谈大道理，先把"明天要交的模块"跑通 |

### 4. 成果与复盘

- 获第九届吉林省中华职业教育创新创业大赛三等奖（2025.12）。
- 最重要的一课：**先把用户的真实约束搞清楚，再决定做什么**。功能多少不是竞争力，可维护性才是。
- 协作方法：把大目标拆成可交付的小步，先保住节奏，再谈优化。

## 二、Courtside — AI 智能篮球训练 App 产品方案

> 产品设计 · 文档阶段（未进入开发）

### 1. 产品目标

让用户只用一部手机，就能获得"像教练一样被指导"的投篮训练：录制 → 实时指导 → 报告回顾 → 下次任务。

### 2. 五类用户画像

| 用户 | 特征 | 核心诉求 |
| --- | --- | --- |
| 业余篮球爱好者（22 岁学生） | 每周打球 2–3 次，无系统训练 | 直观、鼓励式反馈；易上手的计划；约球 |
| 进阶技术流（27 岁业余联赛后卫） | 关注出手角度、速度、一致性 | 骨骼追踪、动作量化、可导出数据 |
| 校队 / 社区教练（38 岁） | 管理球队训练与复盘 | 批量球员识别、团队数据、分层训练 |
| 内容创作者 / KOL（24 岁） | 产出篮球短视频 | 自动高光、模板化包装、一键导出 |
| 周末社交球友（30–40 岁） | 打球为社交与健身 | 轻量、有成就感、即时分享 |

### 3. 双模式价值对比

| 维度 | 训练模式 | 比赛模式 |
| --- | --- | --- |
| 目标 | 动作质量、稳定性、重复性 | 实战表现、战术执行、体能 |
| 核心输出 | 生物力学数据、目标区间、逐次反馈 | 事件流、位置热图、回合分析 |
| 反馈粒度 | 帧级纠正（出手角度、弧高、节奏） | 事件级提示（关键回合、犯规） |
| 成果呈现 | 成长时间轴、一致性报告 | 比赛报告、关键回合高光 |
| 典型 KPI | 进入理想区间占比、动作方差下降 | 净效率、关键时刻得分率、失误率 |

### 4. V1.0（训练模式 MVP）MoSCoW 划分

| 类别 | 功能 |
| --- | --- |
| **Must**（5 项） | 单人训练分析、实时轨迹标绘、即时生物力学分析、个性化训练计划、训练总结报告 |
| **Should**（3 项） | 轨迹回放分析、进步趋势分析、高光时刻自动生成 |
| **Could**（3 项） | AR 训练引导、投篮热力图、无感数据追踪 |
| **Won't**（2 项） | LBS 约球系统、团队 / 比赛分析（推迟至 V2.0） |

### 5. MVP 五步体验闭环

1. 开始训练（单人分析 + 实时轨迹）→「我在被实时分析」
2. 动作反馈（生物力学分析）→「我知道哪里要改」
3. 完成训练（总结报告）→「我真的有进步」
4. 下一步建议（个性化计划）→「我知道下次练什么」
5. 分享激励（自动高光）→「我想给朋友看」

### 6. 数据报告信息架构

- 近期训练快照（今天 / 昨天 / 前天三卡片：命中率、出手数、两分与三分拆分）；
- 命中率变化趋势（一周折线，节点标注具体数值）；
- 个性化「数据头条」（算法生成一句激励式总结 + 训练能量指数）；
- 投篮热力图（球场分区命中分布）。

### 7. 我的收获

- 学会用 MoSCoW 做**减法**：MVP 只保留构成闭环的 5 个 Must；
- 学会把用户画像写成"可验证的场景"，而不是泛泛的人群标签；
- 理解产品设计的核心是**信息密度与决策路径**，不是功能数量。
